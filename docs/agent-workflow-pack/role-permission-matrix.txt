CANTEEN/CAFE MANAGEMENT SAAS - ROLE PERMISSION MATRIX
=====================================================

Purpose:
- Define who can access each dashboard and action.
- Guide route guards, server validation, and RLS policies.

Core rule:
- A user must have an active vendor_members row for the target vendor.
- Role permissions apply only after active membership is verified.

Roles:
- owner
- admin
- manager
- cashier
- kitchen
- accountant

Statuses:
- active: can use allowed features.
- invited: cannot access until activated.
- disabled: cannot access.

8. PLATFORM ADMIN ACCESS
========================

Platform owner/admin:
- May need access for support/debugging.
- Access should be limited, logged, and documented.
- Should not casually browse vendor data.

Agent rule:
- Do not add platform admin access paths without explicit approval.


9. RLS POLICY GUIDANCE
======================

Base check:
- user must be active member of row.vendor_id.

Role check:
- write policies must check role.

Disabled/invited check:
- invited and disabled members must not access protected resources.

Customer/public routes:
- Keep separate from vendor staff dashboards.
- Do not weaken staff table policies to support public ordering.
